## 今日结论

另外两个重要方向继续 WATCH：

机器层给出的 `ad-free experience / affordable ownership / focused workflow / data portability` 不直接升级成产品，它们更适合作为产品原则和筛选条件。

# ACTION

## A1. Intentional Unlock — 带目的解锁的极简 Screen Time 工具

**Decision: BUILD / 进入 48 小时验证**

### Job To Be Done

当用户下意识点开短视频、社交、资讯等高沉迷 App 时，不是一刀切永久封禁，而是要求用户先回答：

> 我现在为什么要打开它？准备使用多久？

在承诺时间内临时放行，到点重新屏蔽，并在结束后做一次极轻的“是否完成目的”复盘。

产品价值核心是 **intentional access contract**，不是另一个复杂的屏幕时间统计 App。

### Evidence class 1 — paid-chart persistence

今日 deterministic report 中，`别刷了喵`：

- 中国付费榜 #34；
- low-rating-count paid app；
- paid-chart presence **9 天**；
- 9 天内最好位置 **#19**；
- 被 Radar 标记为 `small-developer-proxy / persistent`。

Repo evidence:

- `reports/daily/2026-09-17.md`
- App Store app id: `6807461021`

这只说明它持续进入付费榜，不等于下载量或收入。

### Evidence class 2 — current user value signal

当前中国区 App Store 页面显示：

- ¥1；
- 4.8 分；
- 效率分类 #2；
- 7.5 MB；
- 产品明确使用“立约 → 限时 → 到点 → 复盘”闭环；
- 声明数据纯本地、不联网、不上传、无广告、无追踪。

近期评论有非常具体的比较信号：用户称尝试过多款锁手机软件，认为其他产品“功能太冗余”或“收费太高”，而认可这款产品的“确认是否打开、记录使用目标、悬浮计时、复盘目标是否一致”设计；另一条评论认可无额外收费、界面简洁、无广告和倒计时展示。

Primary source:

- https://apps.apple.com/cn/app/id6807461021

> 注：仓库采集时 rating count 与当前网页展示值有小幅差异，可能来自采集时点或页面缓存。评分数量只作为弱代理信号，不用于估算收入/下载。

### Evidence class 3 — official platform feasibility

Apple 官方 Screen Time 技术栈提供：

- Family Controls：授权 Screen Time / parental-control 能力；
- Managed Settings：隐私保护下限制设备行为；
- `ShieldSettings.applications`：对选中的 App 展示 system shield；
- Device Activity：监控使用时间 / schedule / threshold；
- Managed Settings UI：自定义系统 shield 的展示。

Apple 官方文档同时明确：**分发使用 Family Controls 的 App 前必须申请 distribution entitlement**，相关 Screen Time extension 也需要对应申请。这是 MVP 的 P0 技术/上架风险。

Official sources:

- https://developer.apple.com/documentation/screentimeapidocumentation
- https://developer.apple.com/documentation/familycontrols/authorizationcenter
- https://developer.apple.com/documentation/familycontrols/requesting-the-family-controls-entitlement
- https://developer.apple.com/documentation/managedsettings/shieldsettings

### Counter-evidence

这个市场并不空白：

- iOS 自带 Screen Time 已支持停用时间与 App 限额；
- OffScreen 已有成熟的屏幕使用统计、专注计时、禁用 App、实时活动等能力；
- App Store 还有大量“应用锁 / 防沉迷 / 专注”产品。

Sources:

- https://apps.apple.com/cn/story/id1525337854
- https://apps.apple.com/cn/app/id1474340105
- https://apps.apple.com/cn/app/id6477859494

所以不能做“另一个屏幕时间工具”。差异化只能围绕：

> **每次解锁都先声明目的与时长，结束后快速复盘。**

若这个行为闭环不能产生明显价值，项目应直接停止。

### Why now

- 付费榜已有连续信号，且用户明确表达“现有工具太重/太贵”的替代动机；
- Apple Screen Time API 已提供原生执行能力，不需要私有 API；
- 极小的本地应用适合 48 小时 AI Coding 验证；
- ¥1 / 低价买断可以直接测试真实付费意愿。

### 48-hour MVP

只做一个 Job，最多 4 个主状态：

1. **Onboarding / App selection**：申请授权，选择要拦截的 App。
2. **Intent contract**：用户想访问被限制 App 时，填写本次目的 + 使用时长。
3. **Active session**：极简剩余时间状态；到点恢复 shield。
4. **Reflection**：结束后回答“完成目的了吗？”并保存在本地。

明确不做：账号、社交、排行榜、AI 教练、复杂统计、后端、跨平台。

### Pricing hypothesis

第一轮只测试：

- ¥1 低门槛付费下载；或
- TestFlight 验证后测试 ¥6–¥12 一次性买断。

不从现有榜位推断收入。

### Validation target

第一阶段不是 DAU，而是验证行为闭环：

- ≥10 位高频刷短视频/社交的真实用户完成 3 天使用；
- ≥60% 的主动解锁能填写真实目的，而不是机械跳过；
- ≥30% 用户认为“目的 + 限时 + 复盘”比系统 Screen Time / 普通 App blocker 更有价值；
- 至少出现明确的付费意愿，而不是只认可概念。

### Kill criteria

任一条件成立即停止或降级：

- Family Controls distribution entitlement 无法获批或产品形态不符合审核要求；
- 真实用户认为系统 Screen Time / 免费 blocker 已足够；
- “写目的”很快变成无意义机械动作；
- 复盘没有被使用；
- 差异化只能靠 UI，而不是行为机制；
- 付费意愿无法成立。

### iOS-native gate

进入开发必须遵循 `docs/IOS_PRODUCT_GATE.md` 和 `geekjourneyx/ios-native-design`：

- screen contract first；
- SwiftUI native component first；
- system semantic colors / Dynamic Type；
- 44×44 pt hit target；
- VoiceOver semantics；
- Light / Dark；
- Device Hub full-resolution runtime screenshots；
- 真正操作运行中的 primary flow；
- entitlement / permission denied / empty / active / expired states；
- 稳定路径转 XCUI regression；
- Design DoD 才能称为完成。

### Counter-evidence — today is not BUILD

这个方向已经存在多个近似产品：

- `语境英语单词AI`：输入目标单词，AI 直接生成英文 passage + 中文译文；
- `阅读背单词`：AI 推荐适合水平的文章并在阅读中积累生词；
- `读了么`：把生词本词汇自动嵌入后续 AI 文章；
- `生词本·自建词本智能背单词`：用待复习单词生成情景短文。

Sources:

- https://apps.apple.com/cn/app/id6767167318
- https://apps.apple.com/cn/app/id6756994857
- https://apps.apple.com/cn/app/id6758288120
- https://apps.apple.com/cn/app/id1438593050

因此今天的单条 review 是很好的需求线索，但不足以证明新的供给缺口。下一步要找的是：**为什么这些现有产品仍没有解决炭炭用户的需求？**

需要继续捕获：

- 多个主流背词 App 是否重复出现同类评论；
- 用户是否真正想要“生成文章”，还是想要“学习后 3 分钟闭环测试”；
- 阅读、听力、口语哪个 modality 的缺口最大；
- 是否存在可验证的差异化：只用“今天刚学过的词 + 用户薄弱词”，自动生成短测试，而不是泛 AI 阅读。

Decision: **WATCH**。

# REJECT / DO NOT PROMOTE

## R1. Generic “ad-free app”

机器层有大量 `ad-free experience` 评论，但“无广告”只是产品价值属性，缺少一个明确 JTBD。不能仅因为跨 App 抱怨广告就造一个产品。

## R2. Generic “affordable ownership”

用户喜欢低价/买断是商业模式信号，不是产品需求本身。继续用于定价筛选，不单独立项。

## R3. Generic “focused workflow / data portability”

同理，这些是跨产品原则。只有当它们与一个具体用户任务、明确竞品缺口、持续评论证据结合时才升级。

## R4. Reliability

崩溃、识别失败、版本回归首先是竞品质量事件，不自动构成独立产品机会。
